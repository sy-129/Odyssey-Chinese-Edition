# WQ 文件与资源0.11.0：保留文件管理，接入资源工具

## 本轮问题

- 预期：进入原WQ文件管理器，保留文件及应用数据工具，再从真实浏览到的目录进入注入器。
- 实际：旧版以注入器作为启动首页，并另做目标列表。用户截图仍出现青色及“核对2个、过滤375个”的旧版界面，无法满足原浏览器内选择的要求。该截图本身不能证明0.10.1已成功安装或启动。
- 位置：启动场景的rootViewController和资源页自建的应用／目录选择器。
- 复现：打开旧资源首页，对比“文件→应用数据”所列目录与独立目标列表；原工具需绕行文件按钮进入。

## 重做方式

1. 启动恢复原文件管理首页；原容器入口、应用列表、缓存清理、前往路径、应用备份、文件备份和日志均保留。新增“工具→资源注入器”，不替换原工具。
2. 原文件浏览器新增可选的目录选择回调，普通浏览模式保持原来的文件打开、编辑、导入、长按和备份行为。资源页的两个独立选择器已删除。
3. 资源工具选择目录时直接显示同一个WQ浏览器，沿用原目录读取、扫描进度、取消、缓存和搜索。首页与写入前不再独立扫描全部应用，不根据安装列表否决用户所选目录。
4. 原浏览器长按数据目录→“用作资源写入目录”；长按普通文件→“用作导入源文件”。源文件流式复制到本应用的导入区，原源文件不修改。
5. 目标容器按路径中的UUID确定，支持`/var`别名，拒绝把应用数据父目录、非容器名称及越界路径当作单一应用。后续原事务核对容器身份、设备号、文件编号、文件版本与备份哈希。
6. 黑色玻璃与鲜红色保留；产品界面去掉鸣谢／作者区域。首页页脚与资源页显示版本0.11.0（38），避免旧包混淆。版权、GPL许可证和来源声明仍随完整源码分发。
7. 资源页定时器使用弱引用，离开并释放工具后不会因为计时器保留页面，避免多次进入堆积多个工具实例。
