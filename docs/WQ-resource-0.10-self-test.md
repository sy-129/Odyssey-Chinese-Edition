# WQ 资源注入器 0.10.0 修改与验证

感谢宋忆yy二改。原项目 kolbicz/WQFiles；沙盒文件访问技术作者 Taj C，路径查询参考 murk-sus/KAMUI。GPL-3.0-or-later 许可与上游署名保留。

## 未安装应用和重复条目

- 预期：目标选择展示能够核对为现存应用的数据容器，同一目标不重复。
- 实际：用户截图显示未安装应用名称，同一标识重复出现。旧代码直接消费系统数据库候选路径，缺少实际安装状态交叉核对和按应用标识去重。
- 位置：WQResourceUI.m 原目标选择器的数据加载循环。
- 复现：系统数据库含历史或多个容器候选时打开目标选择器；旧代码会逐条加入，未核对实际安装包。
- 修改：新增 WQResourceInventory，优先系统实时安装列表加实际数据目录；不可用时要求目录元数据标识与可读取的现存应用包标识匹配。相同标识和路径去重，路径冲突无法判定时排除。写入前重新核对目标。
- 边界：尚未读取用户手机的真实原始数据库，因此不能据截图确定每条记录究竟是卸载残留还是身份映射错误。受限系统若无法提供安装列表且不能读取应用包，会显示无法验证或空列表；不保证完整列出全部应用，不以历史记录补齐。

## 备份和系统文件保存

自动保存内部恢复快照并校验写入内容；之后导出原件与备份说明，弹出系统“文件”选择保存位置，保存完成后再尝试打开目标应用。取消导出时不打开目标应用，并尝试还原本次写入。

导出结构为 `事务标识/原文件/原文件名` 加独立 `备份说明.txt`，导出后重新核对原件校验值。如果目标原先不存在同名文件，说明会记录，恢复时删除本次新增文件。系统“文件”保存位置由用户选择，不代表可以写入受保护的任意系统根目录。

代码检查发现导出说明与原文件重名会产生覆盖风险，现已分目录并添加实际文件测试：源文件和原件恰好叫“备份说明.txt”时，导出的原件仍保留原字节。

## 游戏完成检测与通知

用户没有现成游戏成功日志或回调，当前提供检测端与游戏/插件接入示例 `examples/WQCompletionReporter.h/.m`。

每次写入生成独立事务、随机标识和资源校验值的请求。游戏或插件必须在其加载逻辑真正成功后报告实际加载资源的校验值。检测端校验匹配回执后，才恢复原件并尝试发本机系统通知。新事务不再因为返回本应用或固定延时就提前还原；没有回执时只等待，用户可以明确手动确认还原。

已添加的协议测试包括缺少回执、错误随机标识、错误资源校验值、正确回执触发还原、不能重复执行已完成事务、有效回执也不能覆盖游戏另外修改的目标文件。

**未完成用户游戏插件的实际接入。** 此版本不能自行判断任意悬浮窗已经开启。接口核对的是接入方报告，不是对不受信任插件的安全认证；拥有目录写权限的一方能构造回执。后台检测可能被系统暂停或终止，返回后继续。系统通知需要用户允许，横幅和专注模式由系统控制；它不是覆盖第三方游戏的悬浮窗。

游戏正常运行也会更新缓存和日志；有些悬浮窗只影响运行内存。文件时间、大小或内容发生变化不能单独作为加载成功证据。

## 界面和中文

- 纯黑背景，系统原生液态玻璃卡片；主按钮改为恶魔图标。
- 启动读取设备物理内存总量、存储空间和可验证应用，再允许选择目标。物理内存总量不是读取游戏运行内存；模拟器截图的内存、存储属于模拟器宿主环境，不是用户手机。
- 首页不再展示原先“基于”页脚，改为“感谢宋忆yy二改”；说明保留原作者和许可证。
- 补充首页、文件浏览器、应用备份、缓存、属性列表、十六进制、数据库查看器和常见文件错误的中文文本。
- 真实应用名称、包标识、路径、文件内容、代码格式和许可证标识保留原值。系统文件选择器由 iOS 提供，跟随系统组件的语言；英文模拟器中该系统界面仍显示英文，不能把它算作完整中文已验证。

## 测试范围

构建使用 macOS、Xcode，设备产物为 arm64、最低 iOS 26，版本 0.10.0／36。主机测试使用真实临时文件，不签发跨应用沙盒令牌；模拟器实际启动应用、操作控件并保存截图。

需要区分：模拟器的缺少权限提示测试不等于真实跨应用读取成功；系统文件选择器打开与取消测试不等于真机导出保存成功；游戏侧示例的临时文件测试不等于用户游戏已加载插件；通知按钮存在不等于已在真实游戏上方收到横幅。iPhone 16 Pro／iOS 27.0.1 的上述场景仍待设备验证。
