# WQ资源注入器0.10.1：应用数据完整目录与鲜红强调色

感谢宋忆yy二改。原作者kolbicz、沙盒文件访问技术作者Taj C及路径查询参考murk-sus/KAMUI的署名和GPL-3.0-or-later保留。

## 用户反馈与原因

- 预期：目标选择器列出“文件→应用数据”里面的全部应用数据目录。
- 实际：0.10.0真机截图只显示2项，过滤360项，选择的VoiceOverTouch也难以辨认；而文件浏览器实际能够列出其他目录。
- 位置：旧WQResourceInventory中的安装列表／安装包Info.plist交叉验证，以及按应用标识排除多个容器的逻辑。
- 复现：在iOS27.0.1能读取数据容器但不能读取对应安装包信息时，打开首页目标选择器，再与“文件→应用数据”对比。
- 原因：旧版把安装包可读和安装状态验证错误地作为数据目录可选择的前提，也把同标识的多个目录全部排除了。这是本次实现的过滤条件不适合用户需求，不能归咎于手机没有数据。

VoiceOverTouch是苹果“旁白”辅助功能相关组件，不是目标游戏，也不是从外部下载来的游戏数据。

## 修改

1. 与原文件浏览器使用相同的读取顺序：先列出 `/private/var/mobile/Containers/Data/Application`，无法直接列出时调用原版目录枚举；不再调用安装API或读取安装包Info来筛掉数据目录。
2. 同一路径只出现一次；同一应用标识的不同目录全部保留。每行显示应用标识和目录UUID，避免把两个不同目录误认成重复项。
3. 本应用自己的目录、名称或标识暂不可读的目录也显示；未知名称按目录编号显示。列表代表数据目录，不再声称已经验证安装状态。
4. VoiceOverTouch显示“旁白（系统辅助功能）”，刷新时也更新已保存选择的旧名称。
5. 写入前仍检查所选目录、对象身份和文件版本，实际读写错误如实显示；列出目录并不代表绕过文件访问权限。
6. 本应用原青色强调文字与按钮改为鲜红色，主按钮红底白字，导航强调色同步；黑色原生玻璃保留。系统文件选择器由iOS提供，主题与语言可能仍跟随系统组件。

## 验证方法与已观察问题

使用原版WQ真实文件读写，在临时目录创建4个数据目录：同一游戏标识的两个目录、本应用目录、没有标识的目录，同时放置普通文件和符号链接。检查4个真实目录全部保留、不依赖安装包、只按路径去重，并按UUID核对实际设备号／文件编号，排除选错对象。

首次新增测试的路径字符串比较失败，诊断显示macOS将同一目录写为 `/var/...` 与 `/private/var/...`。四个目录已经全部列出。测试随后改为核对实际文件系统对象，保留完整性检查，并没有删掉失败断言。

完整候选首轮：92次事务检查与主机回归、严格设备编译及签名通过；UI8项通过，布局用例在执行断言前，XCTest启动阶段无法结束上一轮应用进程，60秒超时。其他测试（含目标选择器、再次启动和系统文件选择器）通过。保留日志与截图并发起重跑；随后又调整目录授权与状态读取顺序，最终结果以下面的最终版本流水线为准，不把首次失败当成通过，也不能据此确认是真机应用问题或测试服务问题。

## 验证边界

临时目录对象一致性测试不等于已远程读取用户手机全部目录；iOS26.5模拟器也不替代iPhone16Pro／iOS27.0.1真机验证。模拟器中手机固定数据根目录不存在时显示真实错误，不放入虚构游戏条目。

本次不更改回执接口：游戏插件尚未接入，不把文件变化当作游戏内开通成功；后台与通知仍受iOS约束。
